# 热量控制模块

## 数据来源

底盘应用从裁判系统回传结构体读取数据，并以 `HEAT_CONTROL_DATA_TOPIC` 主题每 100 ms 发布一次：

- `current_heat`：`referee_info_t.PowerHeatData.shooter_17mm_1_barrel_heat`，当前枪管热量 Q1；
- `heat_limit`：`referee_info_t.GameRobotState.shooter_barrel_heat_limit`，热量上限 Q0；
- `cooling_rate`：`referee_info_t.GameRobotState.shooter_barrel_cooling_value`，每秒冷却值。
- `bullet_heat`：由 `modules/heat_control/heat_control.h` 中的 `HEAT_CONTROL_BULLET_HEAT` 统一配置；修改该宏即可同步应用初始化和算法计算，数值应与裁判系统实际配置一致。

裁判冷却按 10 Hz 结算。模块每次调用读取消息并检查停射条件，目标射频按本地 100 ms 周期更新；本地更新时刻没有与裁判冷却相位同步。

## 使用方式

应用层初始化一个 `HeatControlInstance` 并调用 `HeatControlInit()`。连续发射时调用：

```c
shoot_cmd_send.shoot_rate = HeatControlCalculate(&heat_control, 1);
```

非连续发射时传入 0，模块会复位输出并返回 0。模块会自行从消息中心读取最新裁判数据，不再调用数据更新函数。

参考《枪口射频前馈控制》的持续射击时间预算，将冷却周期与规划窗口分开，每 100 ms 滚动计算未来规划窗口的平均射频：

```text
available_heat = Q0 - Q1
reserve_heat = HEAT_CONTROL_RESERVE_SHOTS * bullet_heat
shoot_rate = cooling_rate / bullet_heat
             + (available_heat - reserve_heat - cooling_rate * settle_period)
               / (bullet_heat * plan_period)
```

`settle_period` 为 `HEAT_CONTROL_SETTLE_PERIOD_S`（0.1 s）；`plan_period` 为独立的 `HEAT_CONTROL_PLAN_PERIOD_S`（默认 1 s，应不小于冷却周期）。规划窗口越长，越早开始降低射频。

热量充裕时结果会被裁剪为最大射频。剩余热量降低到 `reserve_heat + cooling_rate * settle_period` 时，目标射频为 `cooling_rate / bullet_heat`，发弹增热与冷却的平均速率相当。剩余热量更少时继续降低射频，不强制维持这个持续射频，以便恢复余量。只有持续射频不超过最大射频且热量上限足够容纳预留量时，才能在该位置建立平衡。

开始降速的剩余热量阈值为 `reserve_heat + cooling_rate * settle_period + (bullet_heat * max_shoot_rate - cooling_rate) * plan_period`。例如单发热量 10、预留 7 发、冷却 20 点/s、最大射频 30 发/s 时，剩余热量为 200、120、80、72 点对应目标射频 14.8、6.8、2.8、2 发/s。

## 安全策略

- 当前热量达到或超过上限时，目标射速为 0；
- 未收到有效数据、冷却值为负或参数未初始化时，立即复位并返回 0，不等待 100 ms 更新；冷却值为 0 仍按合法数据处理；
- 输出射速限制在 `[0, max_shoot_rate]`；
- 计算使用 `Q0-Q1` 作为可用热量，避免将当前热量误当成剩余热量；
- 预留热量由 `HEAT_CONTROL_RESERVE_SHOTS` 和单发热量共同决定；当前配置 7 发、每发 10 点，对应 70 点预留量。

## 验证与限制

本公式输出连射目标平均射频，不等于实测枪口射频。当前单发/三连发尚未接入统一热量准入，也没有本地发弹记账或裁判热量消息时间戳。预留弹数需要结合回传延迟和在途弹数实测标定，不能仅凭平均热量公式保证每一发都不超限。上机应记录裁判热量、目标射频、拨弹实际速度，确认连续发射时热量在预留边界附近稳定、目标射频接近 `cooling_rate / bullet_heat`。

主机测试位于 `tests/heat_control/heat_control_test.c`，使用实际模块函数、模拟消息中心和计时。覆盖单发热量 2/10 的曲线、立即停射、首发/恢复响应，以及 60 s 连续发弹、100 ms 离散冷却和约一个周期反馈滞后的仿真（逐发检查冷却前热量峰值）。可在项目根目录用 GCC 编译运行：

```text
gcc -std=c11 -Wall -Wextra -Werror -I tests/heat_control/stubs -I modules/heat_control -I modules/message_center tests/heat_control/heat_control_test.c modules/heat_control/heat_control.c -lm -o heat_control_test.exe
```

测试中的平衡结果只适用于模拟参数，不是实机防超限保证。
